# Title: Truncated Bayesian Run-Length Priors for Adaptive-Context Character Language Modeling
# Experiment description: Before training each dataset, compute a smoothed unigram prior from train.bin. Add a vectorized build_runlength_prior(idx, vocab_size, hazard, max_run_len, alpha0, unigram_prior) helper that scans each sequence causally with no gradients, maintains a truncated posterior over recent run lengths plus run-local character counts, and returns next-character log prior probabilities at every batch-time position. Use modest max_run_len values such as 32, 64, and 128 so the method remains cheap for character vocabularies. Extend GPTConfig with use_runlength_prior, runlength_max_len, runlength_hazard, runlength_alpha0, runlength_gate_init, and runlength_gate_max. In GPT.forward(), when prior_log_probs are supplied, compute ordinary tied lm_head logits and add a bounded learned scalar gate times the residual prior prior_log_probs - unigram_log_probs before cross-entropy. Initialize the gate at zero so enabled models begin exactly as the baseline. Modify train(), estimate_loss(), and optional generation diagnostics to compute the causal prior from the visible context, while also reporting GPT-only validation loss with the prior disabled and prior-only validation loss. Compare baseline GPT, fixed-window local count priors, truncated Bayesian run-length priors, shuffled-prior controls, and hazard/max_run_len ablations across shakespeare_char, enwik8, and text8. Report fused validation loss, GPT-only validation loss, prior-only loss, learned gate value, posterior mean run length, reset probability, loss by run-length entropy, loss near natural separators or synthetic prefix splices, train-val gap, total train time, and generation tokens per second.
