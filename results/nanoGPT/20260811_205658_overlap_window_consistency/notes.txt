# Title: Overlap Window Consistency for Boundary-Robust Character Language Modeling
# Experiment description: Modify get_batch() to optionally return contiguous token chunks of length block_size + max_shift + 1. After warmup_iters, every consistency_interval iterations, sample a shift d from values such as 16, 32, or 64 and construct two overlapping windows from the same chunk: X_a = chunk[:, :block_size], Y_a = chunk[:, 1:block_size + 1], X_b = chunk[:, d:d + block_size], and Y_b = chunk[:, d + 1:d + block_size + 1]. Run the model on both windows. Optimize the ordinary next-token cross-entropy on X_a, Y_a, and add a ramped KL consistency loss from detached logits_a to logits_b for target positions appearing in both windows. Use temperature 2.0, ignore overlap positions where the shifted window has fewer than min_context tokens such as 32 or 64, and use a small maximum consistency weight such as 0.05 to 0.2. On non-consistency iterations, train exactly like the baseline. Keep generation unchanged. Extend estimate_loss() to report ordinary train/validation loss, overlap KL under fixed shifts, validation loss by distance from the left window boundary, train-val gap, total train time, and inference tokens per second. Compare against the baseline and a compute-matched two-window control without the KL term across shakespeare_char, enwik8, and text8.
