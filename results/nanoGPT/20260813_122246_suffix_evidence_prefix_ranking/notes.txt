# Title: Suffix-Evidence Counterfactual Prefix Ranking for In-Context Character Reuse
# Experiment description: Keep the GPT architecture, optimizer, ordinary next-character cross-entropy, evaluation path, and generation code unchanged. In train(), after warmup_iters and every prefix_rank_interval iterations, create a counterfactual view by preserving a protected recent suffix such as the final 96 or 128 tokens while replacing the older prefix with prefixes from rolled batch elements. Run both the clean batch and the counterfactual-prefix batch. For protected suffix positions after a short burn-in, compute true-target log probabilities from both views. Add a small ramped ranking loss softplus(logp_counterfactual - logp_clean + margin), weighted by a detached suffix-evidence gate. The gate is active only when a short suffix pattern ending at the current input position, using lengths such as 2 and 4, previously appeared in the clean older prefix followed by the true target, and has lower continuation support in the counterfactual older prefix. Use a bounded support weight such as support / (support + tau), and do not apply ordinary CE to the counterfactual view. Extend estimate_loss() to report ordinary validation loss as the primary metric, evidence-gated ranking accuracy, active gate fraction, clean-to-counterfactual suffix degradation, validation loss on supported suffix-match positions, repeated versus novel target loss, previous-occurrence-distance loss buckets, train-val gap, total train time, and unchanged generation tokens per second. Compare against the baseline, ungated prefix ranking, repeated-character count gating, shuffled evidence gates, and a compute-matched extra-forward control across shakespeare_char, enwik8, and text8.
