# Title: Residual Positional Clocks for Content-Adaptive Character Transformers
# Experiment description: Extend GPTConfig with use_residual_positional_clock, pos_capacity, clock_delta_range, clock_gate_init, and clock_reg_weight. Keep the supervised training sequence length at 256 and use pos_capacity equal to 256 by default, with an optional 512-capacity diagnostic run. In GPT.__init__, add a lightweight clock_proj Linear(n_embd, 1), initialize its weights and bias to zero, and add one learned scalar clock_gate initialized so the residual clock path starts inactive. In GPT.forward(), compute token embeddings normally, predict bounded causal increments delta_t = 1 + clock_delta_range * tanh(clock_proj(tok_emb)), define learned positions with learned_pos[:, 0] = 0 and learned_pos[:, t] = sum_{i < t} delta_i, then mix them with ordinary positions as mixed_pos = arange(T) + sigmoid(clock_gate) * (learned_pos - arange(T)). Add a helper that linearly interpolates the learned position embedding table at fractional mixed_pos values, clamping to the valid range. Train with the ordinary next-character cross-entropy objective and, after warmup_iters, add a small regularizer penalizing mean(delta_t) deviating from 1 and excessive variance in delta_t. Evaluation and generation use the same learned-clock path when enabled, with no auxiliary heads or changed sampling objective. Extend estimate_loss() to report ordinary validation loss at context length 256, validation losses at context lengths 64 and 128, clock gate value, mean and standard deviation of learned increments, and simple increment statistics for whitespace, punctuation, and other characters. Compare the original baseline, a zero-gate clock control, residual positional clocks, and a shuffled-delta control where predicted increments are permuted across batch elements before integration. Report best validation loss, short-context robustness, train-val gap, total train time, and inference tokens per second across shakespeare_char, enwik8, and text8.
