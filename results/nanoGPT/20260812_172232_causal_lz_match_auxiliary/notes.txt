# Title: Causal LZ Match-Length Prediction for Compression-Aware Character Language Modeling
# Experiment description: Modify GPT.forward() to optionally return final hidden states after ln_f. Add a small training-only lz_match_head Linear(n_embd, num_lz_buckets), with coarse buckets for the longest upcoming substring that already appears in the visible prefix, for example 0, 1, 2-3, 4-7, 8-15, and 16-32. Add compute_lz_match_targets(X, Y, max_match_len=32), reconstructing each contiguous chunk as torch.cat([X[:, :1], Y], dim=1). For prediction position t, use only chunk[:t+1] as context and bucket the largest k such that chunk[t+1:t+1+k] occurs fully within chunk[:t+1]. Mask positions too close to the right edge to support the requested future horizon. Because block_size is only 256, implement this with simple per-sequence tuple substring sets on CPU and run it only on auxiliary iterations. Train with ordinary next-character cross-entropy on every iteration. After warmup_iters, every lz_interval iterations such as 4 or 8, use the same forward pass with return_hidden=True and add a ramped auxiliary cross-entropy from lz_match_head(hidden_states) to the LZ buckets, with lambda_lz capped around 0.05 to 0.15. Evaluation and generation use only the normal lm_head. Extend estimate_loss() to report ordinary train/validation loss, LZ bucket accuracy, validation loss by LZ bucket, repeated-substring validation loss, train-val gap, total train time, and unchanged inference tokens per second. Compare against the baseline, a shuffled-LZ-target control, and a simple next-token recency auxiliary across shakespeare_char, enwik8, and text8.
