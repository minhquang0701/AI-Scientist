# Title: Causal Token-Phase Memory for Order-Sensitive Character Language Modeling
# Experiment description: Add an optional CausalTokenPhaseMemory module to GPT before positional embeddings. Extend GPTConfig with use_token_phase_memory, phase_memory_dim, phase_gate_init, phase_decay_init, and phase_max. The module keeps a small real-valued memory made of sine/cosine channel pairs. Scanning each sequence left to right, token idx_t selects a learned bounded phase rotation and a learned write vector; the update is state_t = decay * rotate(state_{t-1}, phase[idx_t]) + write[idx_t]. Project state_t back to n_embd and add it to token embeddings through a scalar gate initialized to a tiny nonzero value such as 1e-3. The disabled path is unchanged. Train with the ordinary next-character cross-entropy objective, optimizer, batching, evaluation, and generation. Compare the baseline, token-phase memory, fixed-phase memory, no-rotation decayed memory, shuffled-token-phase control, and a parameter-matched embedding adapter across shakespeare_char, enwik8, and text8. Report best validation loss, train-val gap, validation loss at context lengths 64/128/256, repeated-target versus novel-target loss, loss by previous-occurrence distance bucket, learned gate and decay values, parameter overhead, total train time, and inference tokens per second.
