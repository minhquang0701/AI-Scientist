# Title: Lag-Queried Past Recall for Addressable Causal Context Representations
# Experiment description: Add a sparse training-only auxiliary objective that asks each final hidden state to recover earlier input tokens when queried by a relative lag. Extend GPTConfig with use_past_recall, past_recall_lags, past_recall_anchors, past_recall_loss_weight, and past_recall_ramp_iters. In GPT.__init__, add a learned lag embedding table for lags such as [2, 4, 8, 16, 32, 64, 128], a small MLP that combines hidden_t with the selected lag embedding, and a past_recall_head projecting to vocab_size. Modify GPT.forward to optionally return final hidden states after ln_f while preserving the standard lm_head logits and next-character cross-entropy behavior. During training after warmup_iters, sample a bounded number of valid anchor-lag pairs with t >= lag, use idx[:, t - lag] as the target, and compute cross-entropy from the lag-conditioned recall head. Balance the sampled pairs across short, medium, and long lags so nearby tokens do not dominate. Optimize total_loss = next_token_loss + alpha_t * past_recall_loss, ramping alpha_t to past_recall_loss_weight. Keep estimate_loss, clean validation, generation, final_info, and inference speed based only on ordinary next-character prediction. Add diagnostics for recall accuracy by lag, validation loss stratified by whether the next token appeared in the recent context, cropped-context validation losses at 64 and 128 tokens, generated repetition/copy metrics, and auxiliary parameter overhead. Compare the baseline against multi-scale lags [2,4,8,16,32,64,128], short-only lags [2,4,8,16], long-only lags [32,64,128], and a shuffled-lag-target control with loss weights 0.02 and 0.05 across shakespeare_char, enwik8, and text8.
