# Title: Train-Only Predictive State Distillation for Character Language Models
# Experiment description: Before training each dataset, scan train.bin only and count suffix-to-next-character statistics for causal context lengths 1 through 5. Retain only suffixes above a minimum count threshold, capped to the most frequent contexts for enwik8 and text8. Convert each retained suffix into a smoothed top-k continuation probability vector over the dataset vocabulary, then cluster these vectors into num_predictive_states empirical predictive states using simple NumPy k-means. Store a mapping from each retained suffix to its cluster ID. Extend GPTConfig with use_predictive_state_aux, num_predictive_states, predictive_state_loss_weight, predictive_state_ramp_iters, max_state_context_len, and min_state_context_count. Add predictive_state_head = nn.Linear(n_embd, num_predictive_states) in GPT.__init__, and modify GPT.forward to optionally return final hidden states while preserving the standard lm_head logits and ordinary next-character cross-entropy. In the training loop, build predictive_state_targets for each batch position by looking up the longest retained visible suffix ending at the current input token, using ignore_index when no reliable suffix is found. After warmup_iters, ramp alpha_t to predictive_state_loss_weight and optimize total_loss = next_token_loss + alpha_t * predictive_state_cross_entropy. Keep estimate_loss, best validation loss, generation, final_info, and inference speed based only on ordinary next-character prediction. Add diagnostics for state-target coverage, predictive-state accuracy, validation loss on covered versus uncovered contexts, validation loss on rare contexts, and cluster entropy. Compare the baseline against num_predictive_states values such as 64, 128, and 256 with predictive_state_loss_weight values 0.02 and 0.05 across shakespeare_char, enwik8, and text8.
