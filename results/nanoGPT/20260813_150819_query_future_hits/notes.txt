# Title: Query-Conditioned Future-Hit Prediction for Predictive Character States
# Experiment description: Modify GPT.forward() to optionally return final hidden states after ln_f. Add a small training-only FutureHitHead that takes a hidden state and a queried token embedding, for example concat(h_t, e_q, h_t * e_q), and predicts binary logits for whether the queried token appears within future horizons such as 4, 16, 64, and 128 characters. On auxiliary iterations, sample batches with block_size + max_horizon + 1 tokens, keep ordinary X and Y for next-character cross-entropy, and sample a modest number of position-query pairs per batch. Query tokens should include the true next token, tokens sampled from later in the same future window, and random vocabulary negatives. Build multi-horizon binary labels by checking whether each queried token occurs within each horizon after the current position. Train every iteration with ordinary next-token CE; after warmup_iters, every future_hit_interval iterations, add a ramped auxiliary BCE loss with lambda_future_hit around 0.05 to 0.15. Use detached token embeddings for the query input as the default so the auxiliary mainly shapes hidden states rather than directly distorting the tied embedding/output matrix. Evaluation and generation ignore the auxiliary head and use the standard lm_head. Extend estimate_loss() to report ordinary train/validation loss, future-hit BCE and AUROC by horizon, repeated-target versus novel-target validation loss, validation loss by future-hit bucket, train-val gap, total train time, and unchanged inference tokens per second. Compare against the baseline, shuffled-query-label controls, and a non-query future-histogram auxiliary control.
