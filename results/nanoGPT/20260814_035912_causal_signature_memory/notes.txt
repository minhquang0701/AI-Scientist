# Title: Causal Signature Memory for Order-Sensitive Character Language Modeling
# Experiment description: Add an optional CausalSignatureMemory module before positional embeddings in GPT. Map idx through a fixed normalized random token-feature table with signature_dim such as 8 or 12. For each sequence, scan left to right and maintain exponentially decayed causal summaries at timescales such as 16, 64, and 256: a first-order trace s1_t and a second-order ordered trace s2_t updated from the outer product of the previous first-order trace and the current token feature. Use normalized EMA-style updates for stability, concatenate all first-order traces and flattened second-order traces, project them to n_embd with a small Linear layer, apply dropout, and add them to token embeddings through a learned scalar gate initialized near 1e-3. Extend GPTConfig with use_signature_memory, signature_dim, signature_timescales, signature_gate_init, and signature_dropout. Keep the optimizer, batching, next-character cross-entropy objective, validation loop, and ordinary generation unchanged except that enabled models recompute causal signature features from the visible context. Compare the baseline, first-order-only signature memory, first-plus-second-order signature memory, shuffled-token-order signature controls, and a parameter-matched embedding adapter across shakespeare_char, enwik8, and text8. Report train and validation loss, best validation loss, repeated-target versus novel-target loss, validation loss by previous-occurrence distance bucket, learned gate value, signature feature norms, parameter overhead, total train time, and inference tokens per second.
