# Title: Delayed On-Policy Replaced-Token Detection for Evidence-Aware Character LMs
# Experiment description: Modify GPT.forward() to optionally return final hidden states after ln_f, and add a small training-only delayed_rtd_head Linear(n_embd, num_rtd_delays), with delays such as [0, 4, 16]. In train(), always compute the ordinary clean next-character cross-entropy on X,Y. After warmup_iters and every rtd_interval iterations, use detached clean logits[:, :-1, :] to sample plausible replacements for X[:, 1:] from a top-k distribution, excluding the observed token so selected corruptions are true replacements. Apply a Bernoulli replacement mask with probability ramped from 0 to about 0.10-0.20, keep position 0 unchanged, and form X_corrupt. Run a corrupted forward with return_hidden=True. For each delay d, train delayed_rtd_head(hidden[:, d:, delay_id]) to predict whether X_corrupt[:, :-d] was replaced, ignoring unavailable positions and using positive-class balancing if needed. Optimize clean CE plus lambda_rtd * delayed_rtd_loss, with lambda_rtd ramped to 0.05-0.15; do not apply LM cross-entropy to the corrupted view. Evaluation and generation use only the ordinary lm_head. Extend estimate_loss() to report clean train/validation loss as the primary metric, delayed RTD AUROC by delay, corrupted-prefix validation loss, expected calibration error, train-val gap, total train time, and unchanged generation tokens per second. Compare against CE-only baseline, immediate-only RTD, uniformly random replacements, shuffled RTD labels, and corrupted-prefix CE recovery across shakespeare_char, enwik8, and text8.
