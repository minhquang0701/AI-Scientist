# Title: Blue-Noise Window Sampling for Redundancy-Reduced Language Model Training
# Experiment description: Keep the GPT architecture, next-character objective, optimizer, evaluation loop, and generation code unchanged. Modify get_batch() so training offsets can be supplied by an OffsetSampler rather than always sampled iid. Implement a blue-noise window sampler over valid memmap offsets: divide the corpus into equal strata, shuffle strata each epoch, sample jittered offsets within selected strata, and reject candidates that fall within a minimum distance such as block_size or 2 * block_size of offsets already chosen for the current batch or stored in a short recent-offset ring buffer. If rejection fails after a small number of attempts, fall back to jittered stratified sampling so the method is robust on small datasets. Compare four samplers: original iid uniform, simple shuffled-stratified, blue-noise without recent-history exclusion, and full blue-noise with recent-history exclusion. Use identical validation and generation for all models. Log ordinary train and validation loss, best validation loss, convergence speed, batch loss variance, offset duplicate rate, recent-window overlap rate, corpus coverage fraction, rejection rate, total train time, and inference tokens per second across shakespeare_char, enwik8, and text8. The hypothesis is that uniform but repulsive crop sampling lowers gradient redundancy and improves sample efficiency or seed stability without changing the model, objective, data, or inference cost.
