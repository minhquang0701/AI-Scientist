# Title: Causal Pair-Compression Supervision for Recursive Character Contexts
# Experiment description: Modify GPT.forward() to optionally return final hidden states after ln_f. Add small training-only auxiliary heads that predict coarse causal pair-compression labels from each hidden state: top phrase length bucket, recursive phrase depth bucket, compression ratio bucket, and number of reductions triggered by the newest token. Implement compute_pair_compression_targets(X), scanning each sequence left-to-right using only the visible prefix X[:, :t+1]. The compressor pushes each new token as a terminal phrase, stores deterministic hash signatures for adjacent phrase pairs seen earlier in the same sequence, and greedily reduces the top stack pair when that pair has occurred before; the new phrase has length equal to the sum of child lengths and depth one plus the max child depth. All targets are bucketed, so the model never predicts arbitrary nonterminal identities. In train(), keep ordinary next-character cross-entropy on every iteration. After warmup_iters, every compression_interval iterations, run the normal forward pass with return_hidden=True and add a small ramped auxiliary loss over the compression labels, with lambda_compression values such as 0.02, 0.05, and 0.1. Evaluation and generation ignore the auxiliary heads and use the standard lm_head unchanged. Extend estimate_loss() to report ordinary train/validation loss as the primary metric, compression-label accuracy, validation loss by phrase-depth and phrase-length bucket, repeated-substring versus non-repeated loss, train-val gap, total train time, and unchanged inference tokens per second. Compare against the baseline, shuffled compression-label controls, a nonrecursive repeated-pair label control, and an LZ-match auxiliary control across shakespeare_char, enwik8, and text8.
